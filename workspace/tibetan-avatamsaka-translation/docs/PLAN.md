# 藏译《大方广佛华严经》翻译与对勘规划

## 目标
将藏文《大方广佛华严经》（德格版 Kangyur ToH 44，含《入法界品》即《善财童子所问品》/Gaṇḍavyūha）翻译为**准确的中文**和**准确的英文**，并与现有汉译版本（八十卷本 T10n0279、六十卷本 T09n0278、四十卷本 T10n0293）及其他相关版本建立精确对照。

## 展示结构要求
每个对照单元需展示：
- 藏文原文（Tibetan original）
- 中文翻译（Chinese translation）
- 英文翻译（English translation）
- 对应汉译八十华严（T10n0279）文本
- 对应汉译六十华严（T09n0278）文本
- 对应汉译四十华严（T10n0293）文本
- 其他可能涉及的佛经版本对应内容

对照粒度建议：以**章节（品/会）** → **段落** → **句/偈颂** 为层级，优先按品目（藏译结构）对齐汉译八十华严的品次，必要时再细分。

## 3. 翻译模型选型（藏译中/英）

翻译目标：**藏文 → 准确中文、藏文 → 准确英文**。需重视术语一致性、段落连贯、对佛典用语的把握。

### 候选模型（调研要点）

| 模型 | 藏译能力 | 上下文 | 本地可用 | 成本 | 备注 |
|---|---|---|---|---|---|
| **Claude Sonnet/Opus/Haiku** (Anthropic) | 较强，近年对藏译关注度提升 | 大（长上下文） | API | 中高 | 指令遵循好，适合术语表约束、逐段翻译 |
| **GPT-4o/GPT-4.1/o3** (OpenAI) | 中强，通用性好 | 大 | API | 中高 | 生态成熟，适合批量处理 |
| **Gemini 2.5** (Google) | 强，长上下文极佳（可处理整卷） | 很大（2M） | API | 较有优势 | 适合整段整卷处理，利于全局一致性 |
| **DeepSeek-V3.1/Reasoning** | 近年进步明显，性价比高 | 大 | API/可本地 | 低 | 中文理解好，可能对藏译需专门提示 |
| **Qwen3** (阿里) | 多语言能力强，部分版本对少数民族语言有优化 | 大 | **可本地（ollama/vllm）** | 低（本地） | 开源可控，适合长时批处理 |
| **Llama-3.1/3.3, Mistral等** | 通用，藏译通常需微调/强提示 | 中大 | 本地 | 低 | 需评估实际效果 |
| **专门模型**：如 NLLB（Meta）等旧模型翻译质量一般，不太适合高精度佛典翻译 | 一般 | 中 | 本地 | 极低 | 仅作参考对比，不推荐作为主力 |

### 推荐策略
1. **先用长上下文模型做段落翻译**（Gemini 2.5/Claude/GPT）配合**术语库**和**对勘范例**
2. **本地化备选**（Qwen3等）用于大规模预处理/初译，API模型用于精校
3. **建立评估集**：选取华严经若干段落（含名相密集处），对比不同模型译文，人工校对后选定主力模型
4. **术语先行**：先整理常用佛教名相（如"如来"、"菩萨"、"法界"、"佛刹"等）藏汉对应、八十华严用语惯例

### 建议首批试用清单
- **主力候选1**: Gemini 2.5（长上下文，利于前后照应）
- **主力候选2**: Claude Sonnet/Opus（指令遵循、术语约束强）
- **经济型**: DeepSeek-V3.1（中文产出好）
- **本地可行**: Qwen3-32B/72B（视硬件而定）

### 对齐流程
1. **底本规范化**：将德格版藏文整理为统一格式（保留页码/行号信息如 `[1a.1]` 等）
2. **分段**：按自然段落、偈颂（gāthā）分段，标注 bam po
3. **汉译映射**：建立藏译品目与八十华严品目的对照表（需调研两套体系的对应关系）
4. **段落对齐**：先用语义相似度（embedding）粗对齐，再人工校对关键段落
5. **翻译**：先生成中英草译，再对照汉译版本校对，确保用语贴合华严文脉
6. **校验**：术语一致性、段落完整性、对照无遗漏

### 展示界面设计（web/）
参考现有 `web/demo/` 的样式，设计对照视图：
- **并排视图**：藏文 | 中文翻译 | 英文翻译 | 八十华严 | 六十华严 | 四十华严
- **逐段切换**：可按品目导航，支持跳转
- **对照高亮**：点击段落时同步高亮各版本对应段落
- **状态标记**：显示翻译状态（草译/校对中/已校对）
- **术语提示**：hover 显示术语对照
