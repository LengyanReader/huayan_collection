# PLAN · 僧传画像

## Goal

设计「高僧画像」维度骨架（声明级数据模型），以跨大宗派取样 + 居士 + 女性做 demo HTML 的**结构验证**。
范围纪律：MVP 结构完备 × verifiability=high（字段可回源、类目可校验）。

## DoD (Definition of Done · objective checks)

| # | 完成标准 | 可验证方式 |
|---|---|---|
| 1 | **维度骨架表**：每维度含 ①定义 ②取值类型 ③回源出处栏 ④原文所载/今人推断 ⑤僧传特有/通用 | 评审 + `check.py` 结构字段非空 |
| 2 | **类目骨架**（僧传十科/门类）名目**回源 `T50n2059` 目录核定** | 出处栏填写 CBETA 链接 + 访问日期 |
| 3 | **取样表**：各大宗派各一位 + ≥1 居士 + ≥1 女性；每位标所属僧传/卷/科（可核） | 出处栏非空; 女性样本出自《比丘尼传》(T50n2063) |
| 4 | **demo HTML**：渲染维度骨架 × 样本，每字段要么带出处要么标〔待核〕 | `python .harness/check.py` PASS |
| 5 | **边界**：本版求结构完备＋取证闭环，不求全量传记数据 | 无未标注占位符 |

## First move

**语料工程 G1·史传部入库**（**✅ 主体已完成 2026-10-17**）：六部大正藏史传已走 CBETA GitHub **raw 媒体型**（`Accept: application/vnd.github.raw`，支持至 ~100 MiB·保 TEI）整本取回存主仓 `data/references/cbeta/`，登 `INGEST_log.md`（字节/git-blob-SHA/本地SHA256/日期）。旧判「>1 MB 需 normal-text 分卷」已推翻。余下经录/东征传/坛经异本属同一脚本待取。**时限**：CBETA Online API 预计 2026-12-01 前后启用 API Key，窗口期内以 GitHub 通道为主。

出口条件：入库清单（经号·题名·册·卷·字节·取回日期·SHA）可复查；每书均用真实字节数与 CBData `filelist` 对照一致；未入库者一律仍标〔待核〕，不得预支为已回源。

## 确认的读法（R5 收敛 · 2026-10-17 用户裁定）

| 项 | 裁定 |
|---|---|
| 档位 | **三档全要**：MVP → Elevated → Exploratory 依次解锁，不停在 MVP |
| 广度/深度 | 按建议：**深度先行**（不空作第二个深填样板），广度（12 人骨架）在其后 |
| 轮次节奏 | **综述批推进·填充另轮**：同一轮只做综述或只做填充，不混轮（免生两套真相） |
| 语料 | 由本会话**检索梳理**通道；未出版/未录入的一手材料（博物馆藏·考古发现）**列入台账待处理**，不伪充已核 |
| 探源（补充裁定 2026-10-17） | 内容之核心在**探源**：重点发掘与使用源头第一手；逐条查其**是否存在 / 在哪里（含架号）/ 是否可用 / 如何取用……参考但不限于此** |
| 受限与传闻（补充裁定） | **需权限·申请·付费·非公开非开源者**（台账 §九 O0–O4）与**无公开路径但有人在说者**（§十 A–F）**各自单独立账**，配待办 T1–T9；**零入库、零上页**，申请与对外接触逐次请示 |
