## §E · 多语 EN 翻译原则（七条 + 结合项）

> 权威源：CLAUDE.md〈多语 EN 翻译原则〉+ [`docs/翻译规范/translation-guide.md`](../docs/翻译规范/translation-guide.md) + [`docs/翻译规范/multilingual-alignment.md`](../docs/翻译规范/multilingual-alignment.md)。落点：[`workflows/translation.md`](workflows/translation.md)。

- **E0 翻译与校对结合**——翻译≠成稿，一律经主编全文审查再 render/commit；含术语一致性、教理准确、结构/引号安全。
- **E1 重实质·不逐字**——义·理·境对等优先，意译优先；名相所指与教理不偏即可。
- **E2 考证与来源分级**——EN 不得超出中文正文范围，不新增年代/史实/观点；无法确认标〔待核〕。
- **E3 固定术语表**——全站统一译法（八识=eight consciousnesses、法界=dharmadhātu、十玄=ten mysterious gates…）；人名循拼音/梵文通行拼写（海云继梦=Haiyun Jimeng，据 huayen.world 官方）。
- **E4 EN 渲染约定**——EN 块 `.en-line` 随全局显隐（默认中英对照）；`title_en`/`intro_en`/`en_body` 分字段；祖师语录正文保中文、EN 用精到阐释转述。
- **E5 YAML 转义纪律**——单引号串内 `\'` 非法用 `''`；撇号（Buddha's）易提前闭合→用双引号串；含中文「」不用双引号包裹；长 EN 用 `|` 块标量（4 空格 key/6 空格内容），**禁单引号包裹英文长文本**；`title_en` 含冒号/撇号须双引号。
- **E6 翻译 API 仅辅助**——在线翻译只作上量初稿、可插拔（无 key 回退子代理）；质量门禁与主编审查**不因 API 放松**。
- **E7 正式用词·不硬翻·不幻觉·无对应即明示**——用学界/佛界通行正式词（梵文转写优先）；禁字面硬翻与自造译名；无通行译名/无把握者明示〔待核〕/〔无通行英译〕，不硬译充数。

## §F · 工程约定 · 反复踩坑的硬规矩（环境/工具副作用）

> 权威源：长期记忆 `common_pitfalls_experience` + [`tools.md`](tools.md) §五/§六。落点：横切 + K-M。

- **F1 CJK 编码**：子进程/输出前设 `$env:PYTHONIOENCODING="utf-8"`；Python 侧 `sys.stdout.reconfigure(encoding='utf-8')`；否则 Windows 控制台 CJK 崩溃/吞 stdin。
- **F2 别用内联 CJK one-liner**：`python -c "…中文…"` 易 SyntaxError；写临时 `.py` 跑，用完删除。
- **F3 PowerShell 约束**：pwsh 7 无 `grep/head/make`；命令用 `;` 串联而非 `&&`；长命令勿超 ~500 字符；`Out-File -Encoding utf8` 可能使中文计数误显 0（用 ASCII 标记反证）。
- **F4 子进程 stdin 隔离**：`stdin=subprocess.DEVNULL`，防 validator 吞交互提示。
- **F5 `SearchReplace` 会重写整份 YAML/JSON**：对**双引号 scalar 内含 `\n` 转义**的字段（如 `chan_authentic_traces.yaml` 的 mermaid）会把转义折成真实换行→事后必 `yaml.safe_load` 对比 `git show HEAD:<path>`；已碎则按 HEAD raw bytes 一次性回内且不再用 SearchReplace 碰同文件。
- **F6 批量正则链接化 `\s*$`（MULTILINE）吞换行**：会吃掉条目末尾 `\n` 致 Markdown 段落塌缩；用 `\n` 显式锚定或匹配后回填空行，写完 `Read` 验证分隔。
- **F7 SIGLA 必反查**：CBETA 册号+番号易张冠李戴（八识规矩颂 T45n1861→实为 T45n1865）；订正要同步 CN/EN 书目 + CN/EN 脚注四处。
- **F8 唯一 builder**：唯一权威 builder = `web/demo/scripts/build.py`（遗留 `build_demo.py` 已删）；`graph.json` 由 `export_sqlite_to_json.py` 产出。
- **F9 扫描排除自指**：`self_evolve` 的 `scan.exclude` 必含 `data/evolution/`、`docs/evolution/`、`next-phase-plan.md`、`CLAUDE.md` 及任何**列举标记 token 的规范文档**，否则标记定义被当作假待办（自污染）。
- **F10 改库即快照** ⭐：`data/catalog/huayan.db` 是 git 外孤本；任何直接写 DB 的脚本（backfill_*/import_*）跑完必须 `db_backup.py --snapshot` 并把 `data/catalog/backups/huayan_latest.sql` 随代码同 commit（2026-09-27 R1 事故后硬约定·详 concerns §7）。
- **F11 写库脚本只用自然键**：重建后 rowid 必漂移（曾致 `backfill_chapters_title_en` 静默 0/41）；`UPDATE/DELETE` 一律用 title_zh 等自然键，严禁硬编码 id/rowid。
- **F12 备份/恢复类工具必须过破坏性演练验收**：不得只在读路径自测——db_backup v1 即在护栏测试中因“先 unlink 后回放”毁掉 live DB；v2 三防线（路径 resolve 后比对/回放前不删目标/只回放到副本）+ `drill_db_restore.py --force` 演练 PASS 才算交付；同理已固为 `test_infra.py` 墓碑测试。
- **F13 破坏性变异的锚点不得写死** ⭐（L.114 立·「老化型假绿」）——反向验证／变异测试的锚点若**硬编码具体数值**（如 `"    total: 27"`），则**数据合法增长后锚点失配 → 变异为空操作 → SKIP**，门禁在最需要它的那天**静默失效**（实测：`_verify_t1_reverse.py` 因 27→31 而反误报 FAIL）。规矩：**锚点随数据解析**——自库读现行值再构造变异（占位符 `@TOTAL@` 之类），并**保留「锚点不存在即不算通过」的前置断言**；**SKIP 不是通过**。凡「写死的数字／文件名／id」充锚点者，一律视为门禁自身之缺陷。

## §G · 存疑分级 · 提交与留痕

- **G1 标记分级**：〔待核〕=真待办（verify/sev4）；〔存疑〕=审慎判定（boundary/sev2）；〔线索〕/〔待补〕=局部/不足；〔并存〕=证据相当而无锤定音；〔无法获取〕=受限并注因。
- **G2 提交规范**：一次净态一提交；描述性信息；本轨专用前缀 `bib(P-track/<X>):`。
- **G3 台账只追加**：`data/evolution/evolution_log.yaml` 每次 auto/human/agent 动作一行、`seq` 单调递增、含 `before/after/evidence`；**被否决提议记 `outcome: declined` 也留痕**。
- **G4 未验不声称完成**：验证未全绿不得标 `passes:true`/不得称"已完成"；交互态**必须真点为验**（headless Chrome/CDP），静态字符串命中≠功能正常。

## §H · 工具/技能选择规矩

- **H1 最小工具集**：职责单一、少重叠；若人类工程师都难判断该用哪个工具，agent 更不能（避免臃肿工具集）。
- **H2 唯一出口**：`db_reader.py`（数据服务）· `build.py`（渲染）· `verify_*`（验收）各为其域唯一权威出口。
- **H3 技能安装纪律**：装前核 install count/来源/星数；**未实际安装并验证者不在文档声称"已具备"**（一律标〔待评估〕/〔待落地〕）。
- **H4 任务起手式**：缺上下文时**先并行** `SearchCodebase` + `SearchMemory`；改某模块前先取该模块知识/规范。
- **H5 外部工具/AI 服务引入验收门**：①只认一手源（官方文档/集成页），营销口径不入决策；②与离线原则（tech-stack 原则③）、〈宁缺不伪〉冲突即一票否决；③能力宣称须用**自有标注数据实测**才算数（尤其中文/文言场景）；④不引入者也要存档评估+重启触发条件（样板：`docs/notes4it/Jev_引入评估.md`）。

## §I · 行文与文体（内容域·认知质量·反 AI 腔）

> 权威源：L.㊽ **文体凡例八条** + L.㊾ **语域学术化/文言残留归零** 批次记录（蒸馏见 [`concerns.md`](concerns.md) §3）+ `zh-academic-register` 技能 + GB/T 15835。落点：C-D。门禁：`scripts/audit_style.py`（✅ v1 报告模式：I2 加粗密度 + I4 套话已可跑；I5/CJK-in-EN 启发式待细化）+ 主编人工回看。

- **I1 章节落事实·不收格言**——小节以具体史实/文献收束，不写格言式、箴言式、“一句话总结”式结尾。
- **I2 加粗克制·辨“装饰”与“批注”**——正文**装饰性/纯强调**的 `**` 应节制（加粗密度指标 9.5/千字仅对装饰性强调适用）；作者**有意的批注性 / 术语首现 / 就用语·行文·字句 提修改线索**类加粗属正当写作手法·**不在清理之列**（执行上遵 §I10 非破坏性原则）。
- **I3 段落参差**——段长自然错落，不追求齐整方块，避免“每段三句”式节奏模板。
- **I4 不用套话·反 AI 腔**——禁“首先/其次/最后/总而言之/综上所述”等空转连接词；反翻译腔（“值得注意的是”“在某种程度上”）与 AI 腔（排比堆砌、万能形上收尾）。
- **I5 语域学术化 + 文言残留归零**——统一现代学术书面语；无故文白夹杂，文言片段仅保留于直接引文（承 E4 祖师语录正文处理）。
- **I6 观点溯源七类标注**——对 **推论/评估/论证/主张/预测/立场/总结** 七类非事实性表述逐条注明依据（何人所论、何典所载、抑或本项目推断）。
- **I7 论断强度校准**——措辞与实际证据强度匹配（例：“决定”→“自然体现”、“证明”→“表明”），证据不足处降格并标〔待核〕/〔存疑〕（承 A0/A2）。
- **I8 数字与体例规范**——依 GB/T 15835 定汉字/阿拉伯数字用法；释题、引号、书名号、CBETA 番号体例全站统一。
- **I9 〔缺口〕EN 端文体规范未建**——中文有凡例、英文尚无对应语域规范；反幻觉“不表演式坦白/不虚构细节”仅散在批次记录，**尚未自动检查**。
- **I10 行文体检默认非破坏性·开放式** ⭐——遇 用语/行文/字句 问题，**一律先以“增加备注·标明修改意见”的方式提出**（如 `〔编注：…〕` 行内标记或独立《修改建议清单》），**不擅自删改作者正文**。仅当硬错（笔误·引号体例·史实错）时可径改且可回退。本条**凌驾 §I 其他各条的执行细节**·与 §A/A2 边界自知 · §G4 未验不声称 一脉。

## §J · 读法原则 · 待人之言（内容域·解读权归属）

> 权威源：L.112 批次记录（2026-10-06，依用户指示立）。落点：C0 考证优先 · C4 穷尽采集 · I10 非破坏性。实证位：`data/research/haiyun_practice_system_evidence.yaml` 之 **S11–S14（自述弯路组）／M8／L5**，已逐字回源并有常设门禁 `verify_haiyun_evidence.py`；另 **S15–S19（三分两用组）／N5／N6**（同批，见 J5），门禁同辖。

- **J1 自述弯路·不作挑错对象** ⭐——法师（及一切著作者）**自述其摸索过程中的弯路与错认**（「不对」「根本上弄错了」「修行不怕错」等），应作**心路历程、摸索实践与精神成长**理解，**不得径作「其判断有误」之证据而挑之**，亦**不必纠结其用词**。此与 §C3 严禁假信息**不冲突**：恰恰相反——自述已陈其误，据实转述即属如实；**捏造其自陈才是造假**。故本文可据一手材料述其走过弯路，但**须用其自用语**，不可代拟「曾自承犯错」之类底本未见之语。
- **J2 J1 之反向亦禁**——**不得**以「法师自陈走过弯路」为据，抹去其已校订之成果，亦不得推出「其体系本无错、免于检核」。**其自述之错，在其体系中有矫正机制**（自省：S12「每一拜都问自己」；外缘：S14「自然有人跑来帮你纠正」）与**方向性**（L5：错在「不肯踏出」，非错在「踏出后有失」）——然 **L1（普贤道须依止善知识）正为其界：摸索有界，越界须依止**。二条当并观。
- **J3 否定性结论（查无）须三项齐备** ⭐——凡据「检索未得」而作「查无」之判，须同时记录 **①检索式全文 ②检索范围 ③命中之排除依据**（判为非目标者之理由）；**三者缺一，则「查无」实为「未检得」之混称**。「查无」与「未查」须严格分记。**且检索式须含目标语义之全部惯用语汇**——本项自伤之例：N1／N4 原仅检「挫折|失败|走错」，漏「弄错／搞错／才发现不对」，致**漏判「自述弯路」达四条**（L.112 已撤回原判，原判留痕不删改）。**再则须逐条区分主语**——原文「你弄错了」（斥听众）与「我…弄错了」（自陈）同式混见，只看关键词极易反向漏检。
- **J4 引证分级之不可越界**——引他人之自述，须分辨其为**自陈**（限其所历，如 S11–S14 之拜佛法门）抑或**教理层面之通说**（如 M8／L5 之论初学者）；以教理通说充作自陈，或以行法之摸索充作「体系建构史之自我否定」，**皆属越界**。取舍之权在读者，不在转述者。
- **J5 自述义与分析义·两用须分记** ⭐（L.112 立）——本文所立**分析框架**之术语，须与该词在**作者／受访者本人语汇中之实际用法**严格分记：同名而两义者，**逐词分标**归属，不得以本文之分析义改其自用之名，亦不得以其自用之义冒充本文之判准。二者各立一表，判准不混。
  - **本项自伤之实例（最重）**：草稿初版将「**建构**」判为最弱一档（C 级·桥接性过渡说明·「仅在无复原/重构依据时才考虑」），**而其自用之义甚为宏阔**——「思想体系的架构、行法修学次第的舖开、**教学体系的建构**、新世代的僧团体制，乃至新古典华严道场宗风、型态的建树」「这些**包罗万象的法界原型**」（S15），且明言「**历来祖师大德在判教以后，创宗立派，都是从工程面来**」（S16）。**致其毕生志业反被本文判为最弱**——此即「据分析义以改自用之名」之病。今正之：分析义另立名「**桥接性建构**」（C），自述义另立名「**体系建构**」（A）。
  - **连带之失**：草稿初版另断言「法师自陈之语中并无此三分」——**此断言经实测推翻**（「建构」33 文件、「重构」25 文件确为其自用语）。**病根在检索范围**：仅检其「原话分析」之语境，未检该词之**一般用例**。故**凡断言某人「未用某词」，须先检该词在其全部语料中的一般用例**，不得只在目标语境内检索。
  - **逐词分标之结果（「复原」一例）：**全库 39 处「复原」**皆生理义**（扭伤复原、复原的能力），**无一用于复原本典原意**——故「复原」**非法师自用语**，只作〔本文判断〕之分析语。**然「未见其语」不等于「其义无据」**：其分析义之立据在 S17（「从贤首国师到清凉国师，这一脉相承里」＋「基因里头」「根要扎实」），**不在「复原」二字之字面**——否则将以不属之辞托意。
  - **不可代拟其语**：「**兼容古今**」全库 **0 命中**，非法师原词；其义在 S15 之「**承先**……**启后**」「古典→新古典」。本文引其意而不代拟其语。**凡以近义词凑成「他说过某语」者，皆属代拟**（同 N3「须连变体一并检索」，此则「**须连词组检、不可逐词凑义**」）。
  - **自述之志业 ≠ 已成之事实**：自述义表所载（如 S15「启后」「新纪元」）属**自我期许**，不得径作已验之结论引之；同须并存其**自限语**（如 S18「我这样讲，只是一个尝试……有待于我们往后的努力」，违者即「掐头去尾」，违编务总则第 3 条）。
- **J6 信度升降由内容性质定，不由引文长短定** ⭐（L.114 立）——**引文补足了，信度不随之升档**。判据只有一条：该条所陈**属何性质**——依实证库 `meta.grading_zh`，**strong 限于直陈自身**（「拼图／摸索／补块／接线／标准作业流程」），**medium 为体系要素之复原、接续、改良**。故一条判释性的原话，即使补成 166 字完整对举，仍属 medium；反之短若系直陈自身，仍可 strong。**以字数升降信度，等于用「证据长度」冒充「证据性质」**——本项之实证：S23 由 10 字补至 166 字，`verify_haiyun_evidence` 回源通过而**信度不动**，判读中明书「不因引文变长而升 strong」。
